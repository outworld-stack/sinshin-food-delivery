About, Terms and temporary closure legitimately permit first creation without an existing record proof. Their advisory locks prevent a concurrent second creation from using that exemption: after the first commit, the next writer must prove the newly existing record. The optional schema token on those routes is therefore not an existing-record bypass. Ordinary creates remain revision-free. Explicit delete routes retain their existing deletion semantics; they submit no replacement document capable of restoring stale Arabic.

`contentSourceRevision` hashes the canonical persisted row and provenance, including `writeRevision`. Missing, null, malformed, old exact-text and foreign tokens fail. `reconcileContentTranslation` advances the durable revision for every accepted write. Field revisions remain independent: non-text changes and reordering fence stale whole-form saves without invalidating unchanged text or triggering translation.

## Collection identity mechanisms

Products carry ingredient IDs in `translationState.collections`; categories do the same for size templates. Terms and article processes carry stable section/process IDs plus child IDs in their parent's namespace. `translationIdentities` is a transient ordered projection, validated for exact known paths, completeness, length, UUID-backed additions, ownership, duplicates and retired IDs. It is removed before persistence. Changed collections never infer ownership from matching text or new array positions.

Legacy unchanged snapshots bootstrap deterministic IDs. An unproven direct reconciliation of a changed legacy collection conservatively assigns new IDs and archives old Arabic rather than attaching it to another source. HTTP update paths reject that missing identity proof. Removed IDs remain retired, including removed untranslated entries.

Article and About retain their existing block document format. List entries carry `props.itemIds`; gallery entries carry `images[].id`. Block ID, type and stable child identity determine ownership; exact current field paths determine writes. The validator rejects changed legacy arrays without IDs, duplicate/cross-block IDs and retired IDs. Duplication creates new block/child IDs. Source-owned order, styles, URLs, images and exact location coordinates remain intact.

Frontend ingredient/template/process/terms actions move, append and remove IDs with their rows. Moving/removing a section rebases its nested collection paths. No editor uses source text to infer a move. The shared draft hook retains the server-issued saved token rather than recomputing a token from edited values.

## Worker, queue and internal exceptions

The worker rereads each selected eligible field before a request, then checks exact source identity/text/revision again under the entity row lock before persistence. It submits only that Persian field. Stable IDs follow a reordered field to its current path. Manual/legacy values and completed automatic fields are excluded. A newer manual edit, changed source, retired identity or superseded Terms version prevents the old result from writing. The store explicitly persists Arabic columns and provenance, with the current About location object retained under lock; translator output cannot replace coordinates or business attributes.

Queue claim/retry/reap operations affect job metadata. Claim serialization excludes a running job's entity while allowing a pending successor for later source changes. Attempt ownership is checked at persistence; success/retry/reap conditions fence obsolete attempts. Single-field previews are read-only and validate stored source identity/revision; new or changed unsaved drafts use explicit one-text previews and are validated again on save. No live translator was used for regression tests.

The following trusted writes intentionally do not require an interactive admin token:

- Article buffered views and product views/sales. They change only counters explicitly excluded from the editor token.
- New record inserts, including development initialization. They bootstrap existing provenance/legacy content without replacing a saved editor snapshot.
- `drizzle/seed.ts` and the independent `drizzle/seed.deploy.ts` entry point. Both were inspected. Their Arabic backfills use atomic conditions requiring exact expected Persian text/document, an empty Arabic column and null provenance. They preserve populated/provenance-managed values. The deployment seed inserts product/article data only into empty tables and does not import or delegate to the development seed. Neither seed was executed in this audit.
- Product-size temporary rename placeholders inside the locked parent transaction. Final stable-ID reconciliation commits with the business values or the whole transaction rolls back.
- Translation worker writes, which use exact per-field proof, row locks and job ownership instead of whole-form client tokens.
- Print configuration and other generic settings writes. They modify separate keys. `SettingsService.set` explicitly rejects both bilingual closure-reason keys; searches found no runtime alternate generic write to those keys.

No separate content import service or additional runtime Persian/Arabic source writer was found. Static Arabic interface dictionaries remain outside this lifecycle.

## Localization and cache review

Products use the same `withSizes/toProduct` localization for list/card/detail/similar paths; category names and individual size names use field validity. Article summaries retain only the provenance needed for title/excerpt display; admin revision tokens use the complete raw row. Public Article/About block documents use a field merge onto Persian source structure. Terms localize each title/item; gallery and packaging filter validity; closure display reads its validated bilingual content snapshot. Missing/stale/pending-review Arabic falls back to current Persian.

Menu/article/packaging caches invalidate after successful writes. About, Terms and gallery currently read persisted content directly; their frontend mutation/query invalidations remain in place. Temporary closure has a local 30-second content cache with a generation check to prevent an old in-flight read from repopulating it after invalidation. Worker failure persistence previously skipped cache invalidation; root has added invalidation after an actual committed error write.
