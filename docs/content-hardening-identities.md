# Content collection identities and mandatory save revisions

This change extends the existing `translationState` JSONB sidecar. Persian collections keep their existing string/section shapes; Arabic columns keep their parallel shapes. No second translation store or alternative block document format is introduced.

`translationState.collections` contains ordered `{ collectionPath, itemIds }` entries. Products use `ingredients`, categories use `sizeNames`, terms use `sections`, and articles use `processes`. Every section/process also has a mapping for its `items` array. A parent ID is its title field ID; item IDs belong to that stable parent's `:items:` namespace. New identities use a prefixed UUID. Editors create an ID when adding an entry and carry it with the entry during text edits, reorder and deletion.

Admin saves submit `translationIdentities`, a transient projection of those mappings. Services require the complete mapping whenever mutable source arrays are submitted. The shared validator rejects unknown collection paths, missing arrays, length mismatches, duplicate IDs, invalid new IDs, another parent's item IDs and retired identities. The server rebuilds and persists provenance under the existing row lock; it does not persist the transient projection or trust client field states.

Reconciliation uses supplied stable IDs for mutations. It never matches changed collections by their text or position. A source edit changes only the field with that identity. Reordering changes the field's current path while preserving valid Arabic bound to the same exact source. Deleting an entry retires its ID, including an untranslated entry's ID. A later replacement receives a new UUID and cannot silently inherit the deleted entry's Arabic. Recoverable Arabic remains in the existing bounded `orphanedFields` archive as `needs-review`.

Legacy saved documents bootstrap deterministic identities from their exact unchanged source paths and existing provenance. The first successful save persists those identities. If a direct legacy reconciliation mutates a collection without identity proof, affected entries receive new identities and existing Arabic is archived for review. HTTP updates reject missing identity projections instead of guessing. This conservative transition preserves stored Arabic and avoids assigning it to another source entry.

The existing sidecar's `writeRevision` advances on every accepted write, including metadata-only and no-op saves and worker persistence. The compact source token hashes the canonical saved record, source structure/order and translation sidecar. Dates and key order serialize consistently; transient request proof fields do not participate. Product/article view counters and product sales counters are explicitly excluded: their trusted counter writes never replace editable source content and must not make unrelated editor drafts stale. Missing, null, malformed, old exact-text and mismatched tokens fail validation. Admin DTOs supply the token generated from the raw stored row so editor projections and computed product/status fields cannot alter its meaning.

Block arrays remain owned by the established block document system. The root change adds optional nested list/gallery identities to that format and its existing field provenance. Content collections do not reinterpret block IDs, coordinates, URLs, styles or animation properties.

Shared regression coverage includes simultaneous multi-field edits with reordering, duplicates, section/item ownership, deletion/replacement, retired untranslated IDs, legacy bootstrap/orphans, transient payload stripping, canonical token serialization and rejection of a reused token after metadata-only or no-op writes. Tests use no live translator.
