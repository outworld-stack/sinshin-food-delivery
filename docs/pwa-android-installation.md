# PWA installation across devices and Android Play Protect

## Installation access

The home page and footer have an **Install Sinshin** action independently of the automatic install banner. In supported browsers it opens a captured native installation prompt immediately from the click. When the browser does not expose a native prompt, or the prompt fails, it opens installation instructions instead. Dismissing an automatic banner does not disable this manual action.

- **Android:** use the browser's Install app / Add to Home screen action. Browsers without a native prompt receive the manual instructions.
- **iPhone / iPad:** open the site in Safari or a current Chrome browser and use Share → Add to Home Screen where available. iPad's desktop-style user agent is recognized, and the compact automatic iOS guidance can open the full instructions. Availability depends on the installed iOS/browser version; Safari is a fallback if that action is missing in another browser.
- **Desktop:** use installation in a supporting browser, or the documented browser-specific menu action where available.
- **In-app browsers:** open the normal site address in an external browser before following that browser's installation steps.

Install access works in development and when service-worker APIs are missing, although an actual PWA installation still depends on the browser's capabilities, a secure site, and platform requirements. Installed standalone windows hide installation UI. Persian and Arabic instructions follow the selected site language.

No website can guarantee an installed app on **every** browser, OS version, or device. Some browsers only offer a shortcut, some do not support installation, and Android/iOS can reject installation under their own policies. Browser use remains available when installation is unsupported or blocked.

## Android warning

Reported message: **“Unsafe app blocked — This app was designed for an older version of Android and does not include the latest privacy protections.”**

This warning concerns the Android package being installed. It is not a JavaScript or service-worker error. The message alone does not identify the package, its target SDK, or the component that generated it; those details must be checked on an affected device.

## What this repository controls

- `apps/web/src/pwa/usePwaInstall.ts` captures the browser's `beforeinstallprompt` event and handles manual installation requests independently of service-worker registration. It does not download or install an APK. Accepting the prompt is not treated as successful installation; the browser's `appinstalled` event or standalone display mode confirms the installed UI state.
- `apps/web/public/manifest.webmanifest` supplies the PWA identity, scope, display options, and icons. Its `id`, `start_url`, and `scope` are consistently `/`.
- `apps/web/Dockerfile` runs `build:pwa`, which builds the website and generates/copies its service worker into the deployment output.
- There is no Android project, Gradle configuration, APK/AAB build, or wrapper source in this repository.

Chrome can generate and install an Android package called a **WebAPK** for a website. That package is managed by the browser's installation infrastructure. A separately distributed APK, including one generated by a PWA packaging service, has its own Android build configuration outside this repository.

The web manifest has no `targetSdkVersion` setting. Changing the site's version, icons, service-worker cache name, or manifest identity is not a repair for an old Android target SDK. A website also cannot read a Play Protect verdict or override it.

## Steps for affected users

1. Open the site's normal HTTPS address directly in an up-to-date Chrome browser. If currently inside a messaging app's browser, use its **Open in Chrome** action first.
2. Update Chrome through its official store, and install available Google Play services / Play Store updates. Restart Chrome and retry installation using the site's Install button or the browser's **Install app / Add to Home screen** action. This checks the browser-managed installation path; it is not a guaranteed fix for a rejected package.
3. If the same warning appears, keep using the website in the browser and report the details below. Leave Play Protect enabled.

Do not clear site data as a routine fix: it can remove sessions and local data and does not update an APK's target SDK. A home-screen shortcut, where the browser offers one separately, is an optional way to reopen the website; it is not the same as installing a WebAPK.

## Information needed to resolve a remaining block

Record the Android version, browser name and full version, exact site URL, installation steps, warning text, and package name if the installer exposes it. Establish whether installation came from the browser's Install action or a downloaded APK/store listing.

| Installation source | Required next action |
| --- | --- |
| Browser-generated WebAPK | Reproduce with current Chrome and collect the affected package/browser details for a Chromium/WebAPK installation report. A website deployment cannot rebuild this Android package directly. |
| Downloaded APK, store package, or external PWA wrapper | Obtain that project's Android sources and inspect its generated package's target SDK. Update its build tools and target SDK to the applicable current Android/store requirements, implement any required behavior and permission changes, then build, sign, test, and redistribute it through the existing release process. |

For an available APK, Android SDK's `apkanalyzer manifest target-sdk path/to/app.apk` can verify its declared target SDK. Compare the actual package with the affected Android version; do not assume that the oldest installable target also satisfies current store policy. Android's OS installation restrictions and Google Play Protect checks are separate mechanisms.

After remediation, verify a fresh installation on an affected Android version with Play Protect enabled, launching from the home screen, and a subsequent PWA update. The local service-worker tests cannot exercise Google's package generation or an Android Play Protect decision.

The local `bun run test:pwa-install` script covers native prompting during click activation, duplicate clicks, failed/consumed prompts, iOS and iPad detection, installation help without service-worker support, persistent banner dismissal, installed mode, blocked storage, and event/timer cleanup. Verify the browser menu instructions on representative Android, iOS, and desktop devices after deployment.
