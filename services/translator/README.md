# سرویس مترجم آفلاین — راند ۳۵

> میکروسرویس پایتونی ترجمه‌ی ماشینی **فارسی → عربی** برای محتوای دوزبانه‌ی
> سین‌شین: مدل **NLLB-200-distilled-600M** کوانتیزه‌شده به **int8** با
> **CTranslate2**، پیچیده در **FastAPI/uvicorn** روی پورت `8300` — فقط در
> شبکه‌ی داخلی compose. این سرویس کاملاً **آفلاین** است: مدل در زمان بیلد
> داخل ایمیج پخته می‌شود و در زمان اجرا صفر اینترنت لازم دارد.

این سرویس خودش **هیچ‌چیز در دیتابیس نمی‌نویسد**. API اصلی (Elysia/Bun) آن
را در `http://translator:8300` صدا می‌زند و از طریق **صف ترجمه** نتایج را
در ستون‌های عربی (`ar`) جداول محتوا ذخیره می‌کند — با پرچم `arAuto=true`
که در پنل ادمین با بج «خودکار» مشخص می‌شود.

---

## ۱) بیلد

```bash
docker compose build translator
```

- بیلد **دومرحله‌ای** است (ببینید `Dockerfile`):
  - مرحله‌ی `converter` فقط زمان بیلد اجرا می‌شود و **یک‌بار اینترنت** لازم
    دارد: مدل fp32 (‏~۲.۴GB) و torch واریانت CPU را دانلود می‌کند و خروجی
    int8 (‏~۶۰۰MB) می‌سازد. این مرحله هرگز وارد ایمیج نهایی نمی‌شود.
  - مرحله‌ی `runtime` ایمیج نهایی ~**۱.۲GB** را می‌سازد: `python:3.11-slim`
    + وابستگی‌های سبک (بدون torch!) + مدل پخته‌شده در `/model` + `app.py`.
- پس از بیلد، **زمان اجرا هیچ اینترنتی لازم نیست** — نه دانلود مدل، نه
  فراخوانی بیرونی. مدل عمداً داخل ایمیج است (نه volume) تا سرویس
  stateless و آفلاینِ واقعی بماند.
- بیلد علاوه بر میرور docker.io (برای بیس `python:3.11-slim`) به دسترسی
  مستقیم به `pypi.org` ،`download.pytorch.org` و `huggingface.co` نیاز
  دارد — فقط در همین مرحله.

## ۲) اجرا

در استک تولید با خود `docker-compose.yml` بالا می‌آید (شبکه‌ی internal،
بدون پورت بیرونی). برای توسعه‌ی محلی جداگانه:

```bash
docker compose -f docker-compose.dev.yml up -d translator
# → http://127.0.0.1:8300
```

## ۳) API

### سلامت — سبک و بدون فراخوانی مدل

```bash
curl -s http://127.0.0.1:8300/health
```

```json
{"ready": true, "model": "nllb-200-distilled-600M-int8", "device": "cpu", "src": "pes", "tgt": "arb"}
```

### ترجمه

```bash
curl -s http://127.0.0.1:8300/translate \
  -H 'Content-Type: application/json' \
  -d '{"texts": ["سلام دنیا", "این رستوران سین\u200cشین است"], "source": "pes", "target": "arb"}'
```

```json
{"translations": ["مرحباً بالعالم.", "هذا مطعم سين شين"]}
```

- `texts`: آرایه‌ای از ۱ تا **۶۴** رشته؛ هر رشته ۱ تا **۳۰,۰۰۰** کاراکتر.
  خارج از این محدوده → خطای ۴۲۲ با پیام فارسی.
- `source`/`target` اختیاری‌اند (پیش‌فرض `pes`/`arb`). فقط همین دو کد —
  به‌همراه معادل کاملشان `pes_Arab`/`arb_Arab` — پذیرفته می‌شود؛ کد مبدأ
  برابر مقصد → خودِ متن‌ها بدون تغییر برمی‌گردند.
- **متن‌های چندخطی**: هر متن به خط تقسیم می‌شود، خطوط خالی/فاصله‌ای
  دست‌نخورده در جای خودشان می‌مانند و بقیه‌ی خطوطِ همه‌ی متن‌ها در «یک»
  فراخوانی مدل ترجمه و با حفظ ترتیب بازچینی می‌شوند.

> **نکته‌ی فنی مهم (کد زبان):** قرارداد سطح API همان `pes`/`arb` راند ۳۵
> است، اما NLLB با کدهای کامل FLORES-200 (`pes_Arab`/`arb_Arab`) آموزش
> دیده و کدهای کوتاه در واژگانش صرفاً توکن‌های معمولی‌اند — استفاده‌ی
> مستقیم از آن‌ها در `target_prefix` خروجی نامرتبط می‌دهد. سرویس این
> نگاشت را داخلی انجام می‌دهد؛ فراخوان نیازی به تغییر ندارد.

## ۴) منابع و رفتار

| موضوع | مقدار/توضیح |
|---|---|
| RAM در زمان اجرا | ~۱.۵–۲GB آزاد لازم دارد (مدل int8 + فضای beam search) |
| CPU | `intra_threads = تعداد هسته‌ها − ۲` (حداقل ۱)؛ کالیبره برای ۲ هسته |
| سرعت | ~۱–۳ ثانیه برای متن کوتاه روی ۲ هسته |
| هم‌زمانی | **قفل تک‌دسته‌ای**: در هر لحظه فقط یک batch به مدل می‌رسد؛ درخواست‌های دیگر در صف می‌مانند (مدل گلوگاه است و این جلوی ترکیدن RAM را می‌گیرد) |
| سقف خروجی | حداکثر ۵۱۲ توکن خروجی برای هر خط (`max_decoding_length`) — متن‌های خیلی طولانی ممکن است خلاصه شوند |
| حافظه‌ی بعد از restart | مدل دوباره از دیسک ایمیج بارگذاری می‌شود (~۱۰–۴۰ ثانیه، بسته به دیسک) |

## ۵) محدودیت‌ها

- **کیفیت ترجمه‌ی ماشینی**: NLLB مدل خوبی است ولی بی‌نقص نیست؛ به همین
  دلیل پنل ادمین خروجی ماشینی را با بج **خودکار** (‏`arAuto`) علامت می‌زند
  تا کاربر انسانی بازبینی/ویرایش کند. ذخیره‌ی دستی ادمین همیشه برنده است و
  ستون‌های پرِ دستی هرگز بازنویسی نمی‌شوند.
- تا ترجمه‌ی ماشینی انجام نشود، ستون عربی خالی می‌ماند و کاربر عربی
  همان محتوای فارسی را می‌بیند (‏COALESCE رارد ۳۴).
- اگر این سرویس پایین/غیرفعال باشد، صف ترجمه در API فقط pending می‌ماند
  و چیز دیگری از کار نمی‌افتد.
